# 一条抽卡记录的生命周期

官方 api 返回--解析--生成business_key--查重--不存在--插入数据库--后处理计算

# 表结构

## 用户表

user 系统用户

- id PK
- username
- password_hash
- created_at

扩展登录功能

## 游戏账号表

game_account 游戏账号

- id  PK 系统内部主键
- user_id  FK->user.id
- game_uid  游戏uid
- server_id  服务器id
- nickname（待扩展）
- created_at（待扩展）

user 1 -> n game_account

**UNIQUE**(server_id, game_uid)

## 游戏资源表

game_resource 游戏资源

- id  PK
- resource_id  **UNIQUE**
- resource_name
- resource_type
- quality_level

## 卡池表

gacha_pool 卡池

- id  PK
- pool_code  **UNIQUE**
- pool_name
- pool_type

## 抽卡记录表（只读）

api_gacha_record

- id  PK
- account_id  FK->game_account.id
- pool_id  FK->gacha_pool.id
- pool_type
- resource_id  FK->game_resource.id

- business_key  **UNIQUE**

- import_task_id  FK->api_import_task.id

- draw_time  业务时间，实际抽取时间
- in_second_seq

- api_draw_order（经常查询）  计算得到的顺序
- logical_order  拼接完成后的顺序，BIGINT，使用稀疏序

- created_at
- updated_at

舍弃is_up，计算代价很低，改为动态计算。

构造业务唯一键，作为去重依据。

business_key:  
CHAR(64)  
SHA256(uid + pool_id + resource_id + draw_time + in_second_seq)

## 手动导入数据表（允许编辑）

manual_gacha_segment

- id  PK
- account_id  FK->game_account.id

- pool_type
- pool_id  FK->gacha_pool.id

- resource_name（五星名称）
- resource_id  FK->game_resource.id（匹配id）

- pity_count（消耗抽数）

- manual_draw_order
- logical_order 拼接时使用的顺序

- batch_id  FK->manual_import_batch.id

<!-- - insert_after_record_id（插入位置） -->

- created_at
- updated_at

## 导入任务表(api)

api_import_task

- id  PK
- account_id  FK->game_account.id

- status

- request_cursor  请求游标
- card_pool_id

- imported_count 导入记录条数

- created_at

## 导入批次表(manual)

manual_import_batch

- id  PK  导入批次
- account_id  FK->game_account.id

- created_at
