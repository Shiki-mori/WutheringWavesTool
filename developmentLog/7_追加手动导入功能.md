# 手动导入功能

## 需求描述

由于官方链接仅保留六个月的记录，用户在使用本项目时，可能会需要手动导入以前的记录。手动导入可能发生在初次使用本项目，需要手动导入以前的数据；或经历过长期未使用本项目，再次使用本项目时手动导入。

手动数据仅有卡池类型（角色，武器，常驻），名称（只有五星名称），抽数，等级（只支持5星）字段信息，没有其他原始属性。

手动数据需要与通过链接获取到的数据进行明确的区分。  
手动数据需要有一定的内部顺序。该顺序可由直接使用用户导入的顺序。  
手动数据不应与链接数据重叠。（后续可能将支持此功能）  
需支持多次导入。  

手动数据将与链接数据拼接起来。拼接顺序将由用户指定。用户进行一次手动导入，同时指定该批数据插入的位置。需判断手动导入的合法性。  
即支持任意位置插入的有序序列。

后续对拼接起来的完整数据进行分析。

在进行排行榜这类功能实现时，手动数据不可作为有效数据。

手动数据需支持修改，删除等操作，但链接数据不允许。

拼接结果与链接数据分开存储。

## 思路

为数据表新增词条：

is_manuals TINYINT(1) NOT NULL DEFAULT 0 COMMENT: 是否手动导入  
manual_batch_id BIGINT NULL COMMENT: 手动导入批次ID  
manual_order INT NULL COMMENT: 手动数据内部顺序  
data_source ENUM('official', 'manual') NOT NULL DEFAULT 'official': 数据来源

手动数据仅有名称，抽数，等级（只支持5星）字段信息，其他信息全部为null。

手动数据的实际日期设置为NULL，另设global_order BIGINT NOT NULL，作为真实排序的字段。

>对于手动数据，设global_order = manual_batch_id + manual_order？  
不应使用这个逻辑。用户每使用一次手动导入，都会指定插入位置。批次编号不能表示实际排序信息。有可能批次编号靠后的反而在前面。

”允许用户指定插入位置功能“，会让任何基于batch的顺序编号失效。需要更换思路。  

该需求的本质是：支持任意位置插入的有序序列。  
常用解决方法是稀疏序。

## 拆分两个系统

原始事件系统 api_gacha_record  
历史补丁系统 manual_gacha_segment  
两个系统数据分开存储，互不干扰
